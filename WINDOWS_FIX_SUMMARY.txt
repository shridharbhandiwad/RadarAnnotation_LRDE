ROOT CAUSE
================================================================================

The CMakeLists.txt was trying to LINK to onnxruntime.dll directly.

On Windows, you CANNOT link to .dll files!
You must link to the IMPORT LIBRARY (.lib file).

Wrong (old):
  set(ONNXRUNTIME_LIBRARIES ${onnxruntime_SOURCE_DIR}/lib/onnxruntime.dll)

Correct (new):
  set(ONNXRUNTIME_LIBRARIES ${onnxruntime_SOURCE_DIR}/lib/onnxruntime.lib)

================================================================================
TECHNICAL EXPLANATION
================================================================================

Windows Dynamic Libraries Have TWO Files:

  onnxruntime.lib  → Import library (used at LINK time by compiler)
                      Contains symbol table for linking
                      ~100 KB

  onnxruntime.dll  → Dynamic library (used at RUN time by executable)
                      Contains actual executable code
                      ~5-50 MB

CMake's target_link_libraries() needs the .lib file!
The .dll is automatically loaded at runtime (must be in same directory as .exe)

Linux/macOS only have ONE file (.so or .dylib) that serves both purposes.

================================================================================
WHY THIS IS THE CORRECT FIX
================================================================================

This is not a workaround - it's the PROPER way to link ONNX Runtime on Windows.

Microsoft's official documentation and CMake best practices both specify:
  - Use .lib (import library) for target_link_libraries()
  - Deploy .dll to same directory as executable for runtime
  - Never try to link directly to .dll files

The previous code worked on Linux because .so files serve both purposes.
Windows requires explicit separation of compile-time and runtime libraries.
