Your CMake configuration was failing during the C compiler test with:

The compiler command being run was:
  
  C:\msys64\mingw64\bin\cc.exe -Wa,-mbig-obj 
    -Dmax(a,b)=((a)>(b)?(a):(b)) 
    -Dmin(a,b)=((a)<(b)?(a):(b)) 
    -o ... -c testCCompiler.c

================================================================================
ROOT CAUSE
================================================================================

The preprocessor definitions with `>` and `<` characters are being interpreted
as SHELL REDIRECTION OPERATORS by Windows cmd.exe, not as part of the compiler
flags.

Windows sees:   -Dmax(a,b)=((a)>(b)?(a):(b))
                              ↑
                              Tries to redirect to file "(b)"
                              Invalid filename → error

This works on Linux but FAILS on Windows due to different shell parsing rules.

================================================================================
THE SOLUTION
================================================================================

✅ YOUR CODE IS ALREADY CORRECT!

Your CMakeLists.txt (lines 36-51) correctly uses:
  - add_compile_definitions(NOMINMAX) ✅
  - Does NOT include the problematic CMAKE_C_FLAGS ✅

The max/min macros are added by fix_build_dependencies.py which patches the
cpuinfo source files directly (the RIGHT way).
