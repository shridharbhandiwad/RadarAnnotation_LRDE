KEY INSIGHTS (Windows):
───────────────────────
  💡 The "eight_bit_int_gemm" issue is MinGW-specific and is automatically
     patched by the CMakeLists.txt (lines 36-291)
  💡 MinGW requires special handling of max/min macros
  💡 Build times: 20-45 minutes on first build (downloads dependencies)
  💡 Subsequent builds: 2-5 minutes (only recompiles changed files)
  💡 Use "MinGW Makefiles" generator, not "Unix Makefiles"

COMMON WINDOWS ISSUES:
──────────────────────
  ❌ "mingw32-make not found"
     → Install MinGW-w64 or MSYS2 and add to PATH

  ❌ "cmake not found"
     → Download from https://cmake.org/download/ and add to PATH

  ❌ Build fails with "cannot find -lonnxruntime"
     → Clean rebuild: rmdir /s /q build && rebuild_windows.bat

  ❌ "The system cannot find the path specified"
     → Use Windows paths with backslashes or forward slashes
     → Example: cpp_inference\build or cpp_inference/build

  ❌ Long build times (>1 hour)
     → This is normal for first build (downloads TensorFlow Lite)
     → Subsequent builds are much faster

MINGW PATCHES INCLUDED:
───────────────────────
  The CMakeLists.txt automatically applies these patches for Windows/MinGW:
  
  1. Disables problematic eight_bit_int_gemm target
  2. Removes min/max macro definitions that conflict with Windows headers
  3. Adds NOMINMAX definition to prevent Windows.h conflicts
  4. Adds -Wa,-mbig-obj flag for large object files
  5. Patches gemmlowp and TensorFlow Lite CMakeLists.txt files

  These patches activate automatically when building with MinGW!
